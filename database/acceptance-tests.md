# Pruebas de aceptación ACJ Camp

Los casos requieren una base PostgreSQL con PostGIS, variables configuradas y dos sesiones de navegador. Ejecutar después de instalar `schema.sql` (o `migrate.sql` si la base ya existía). `Satisfecho` significa verificado de extremo a extremo; el build por sí solo no confirma comportamiento con datos.

| Caso | Comprobación | Resultado esperado | Estado |
| --- | --- | --- | --- |
| Registro único | Registrar dos veces el mismo correo | El segundo intento se rechaza y no expone detalles internos | No satisfecho: pendiente de ejecutar con PostgreSQL |
| Director de club | Iniciar sesión como director, registrar varios clubes para su iglesia, verlos/editarlos y asignar/retirar líderes; intentar modificar un club ajeno | El director gestiona todos sus clubes y líderes válidos; una petición sobre un club ajeno recibe HTTP 403 | No satisfecho: pendiente de probar altas múltiples con cuentas de Director |
| Alta de iglesias y clubes por rol | Intentar registrar iglesia y club como líder, director y admin | Solo el director puede registrar iglesia y club; líder y admin reciben HTTP 403; Admin conserva el borrado protegido por dependencias | No satisfecho: se verificó HTTP 403 del líder; falta probar altas como director y admin |
| Perfil de líder y dashboard | Iniciar sesión como líder, editar nombre/teléfono, cambiar contraseña y abrir el dashboard | El perfil se actualiza para la propia cuenta y el líder puede ver la portada/dashboard | No satisfecho: pendiente de ejecutar con PostgreSQL |
| Límite por IP | Enviar seis intentos de login en un minuto desde una IP | El sexto intento recibe HTTP 429 | No satisfecho: pendiente de ejecutar con API desplegada |
| Confirmación del lugar en 48 h | Solicitar una reserva, confirmar como líder antes del límite y dejar otra vencer | El líder confirma tras contactar al lugar; la aceptada ocupa fechas y la vencida se cancela/libera automáticamente | No satisfecho: pendiente de probar con cuentas y simular vencimiento |
| Solicitud y confirmación de reserva | Crear una reserva con líder, club, motivo y rango de fechas; confirmar como líder; intentar reservar fechas coincidentes desde otra cuenta | Admin ve los datos y plazo; el líder confirma directamente; pendiente no bloquea; confirmada aparece ocupada y el segundo intento se rechaza | No satisfecho: pendiente de probar el flujo con cuentas de usuario |
| Bloqueo de cuenta | Fallar cinco veces para una cuenta existente | La cuenta queda bloqueada durante 15 minutos y se libera después | No satisfecho: pendiente de ejecutar con PostgreSQL |
| Lugares y aprobación | Crear lugar como director; aprobar y rechazar como admin | La propuesta no aparece al público hasta aprobarla | No satisfecho: pendiente de ejecutar con PostgreSQL y Cloudinary |
| Alta y edición propia | Crear como usuario autenticado, verlo en Mis lugares y editarlo | Se conserva el propietario, se actualizan campos y el estado de aprobación no lo puede cambiar el autor | No satisfecho: base local en recuperación; UI/API implementadas |
| Distancia PostGIS | Buscar autenticado con iglesia georreferenciada | Devuelve solo lugares dentro de 50 km y calcula distancia en SQL | No satisfecho: pendiente de ejecutar con PostGIS |
| Reserva sin conflicto | Crear reservas contiguas y luego una con fecha compartida | La contigua se acepta; la solapada responde HTTP 400 incluso en concurrencia | No satisfecho: falta instalar `btree_gist` en la base local |
| Cancelación e historial | Cancelar una reserva propia y consultar el historial | Cambia a cancelada, conserva el registro y libera las fechas | No satisfecho: pendiente de ejecutar con PostgreSQL |
| Reseña con cuenta | Iniciar sesión como usuario y publicar una reseña sin reserva; repetir con reserva completada propia y probar una reserva ajena/no completada | Cualquier cuenta activa puede reseñar; una reserva se asocia solo si está completada y pertenece al usuario y lugar; autor, calificación y fecha aparecen | No satisfecho: la API permite reseña sin reserva; falta validar el flujo visual con dos cuentas |
| Una reseña por usuario y lugar | Publicar otra reseña para un lugar donde el usuario ya opinó e intentar editar la reseña de otro usuario | La segunda publicación actualiza la reseña propia; no crea duplicados; solo el autor o admin puede editar/eliminar | No satisfecho: migración aplicada y consultas comprobadas; falta probar permisos con dos cuentas |
| Panel y Excel | Abrir reportes como admin y descargar el archivo | KPIs, zona, popularidad y archivo `.xlsx` con encabezados en español | No satisfecho: pendiente de ejecutar con PostgreSQL |
| Gráficas del panel admin | Abrir Estadísticas; cambiar 6/12 meses, usar el zoom del gráfico y alternar reservas/calificación en lugares populares | Gráficas muestran los reportes actuales, tooltips y controles responden; el resto del panel sigue accesible | No satisfecho: compilación correcta; falta interacción visual manual |
| Usuarios por rol y afiliaciones | En Admin > Usuarios, filtrar administradores/directores/líderes y revisar personas con clubes | Conteos y filtros coinciden; cada director/líder muestra su iglesia y clubes asociados; asociaciones ausentes se identifican como tales | No satisfecho: endpoint comprobado con datos locales; falta revisión visual manual |
| Directorio de iglesia y clubes | Abrir Admin > Iglesias y clubes; inspeccionar directores, líderes y asignaciones | Cada persona aparece bajo su club e iglesia; contactos y estado permiten reconocer a quién pertenece | No satisfecho: consulta del directorio comprobada; falta revisión visual manual |
| Reservas con afiliación | Abrir Admin > Reservas y Mis reservas con una reserva vinculada a club | Se muestran solicitante, club e iglesia; reservas sin afiliación muestran un texto explícito | No satisfecho: joins de club/iglesia comprobados; falta revisar ambas pantallas |
| Reseñas con afiliación | Abrir la ficha de un lugar con reseñas de usuarios asociados a clubes | Cada reseña muestra la iglesia y clubes del autor sin duplicar reseñas | No satisfecho: API devuelve asociaciones; falta validar visualmente con autores de más de un club |
| Explorar y ver mapa | Abrir `/buscar`, usar la búsqueda y entrar a una ficha; luego abrir `/mapa` | `/buscar` muestra tarjetas de lugares activos con foto, dirección y datos; `/mapa` conserva el mapa interactivo por separado | No satisfecho: ambas rutas responden y la API devuelve lugares; falta probar navegación visual y búsqueda |
| Clima por coordenadas | Abrir fichas de lugares con distintas coordenadas y desplegar la previsión | Clima actual y tres días corresponden a latitud/longitud del lugar; caché de 15 min; si Open-Meteo falla, reserva y ficha continúan utilizables | No satisfecho: endpoint probado con un lugar y Open-Meteo respondió; falta comprobar el comportamiento visual y el fallo externo |
| Prioridad de reserva | Abrir una ficha en móvil y escritorio y seguir el acceso rápido Reservar | Reserva tiene prioridad; clima ocupa una franja compacta con previsión plegable; Reseñas conserva su acceso y contenido | No satisfecho: compilación correcta; falta revisión visual en ambos tamaños |
| Importación de iglesias OSM | Como admin, buscar iglesias adventistas de La Paz, revisar candidatas/duplicados, importar algunas y volver a buscar | Vista previa no escribe; duplicados no se seleccionan; la importación confirmada crea iglesias (no campamentos), registra al admin y aparece en la capa de iglesias | No satisfecho: endpoints protegidos; OSM agotó el tiempo de espera durante la comprobación; falta probar cuando el proveedor responda |
| Migraciones aditivas | En una copia de una base existente, ejecutar `migrate-iglesias-creado-por.sql` y `migrate-resenas-cuenta-usuario.sql`; comprobar antes/después los conteos | Añaden auditoría de creador y permiten reseñas sin reserva con una reseña por usuario/lugar; no borran usuarios, iglesias ni reseñas | Satisfecho: aplicadas en la base local; columna e índice verificados |
| Capa de campings OSM | Activar/desactivar puntos, mover el mapa y actualizar en La Paz | Aparecen campings/caravanas de OSM, sus fichas abren el objeto fuente y la consulta sigue el área visible | Satisfecho: el endpoint devolvió 7 puntos y el mapa mostró 5 dentro del viewport móvil |
| Compilación frontend | `npm run build --prefix frontend` | Vite genera `frontend/dist` sin errores | Satisfecho: build local completado |
| Sintaxis backend | `node --check` en controladores y rutas editados | Sin errores de sintaxis | Satisfecho: chequeo local completado |
